# Git
> 记录软件项目在不同时间点的状态
> 每个Commit对应历史中的一个确定状态
> 让历史可检验，备份与恢复，一个 change 对应一个意图
> 避免 AI-native 导致的一团混沌，现在还没有无限大能力模型

## Git的不同区域
- 工作区
- 暂存区
- 本地仓库

## 多分支开发
> 解决多人或者多个任务同时开发的问题。

### Merge和Rebase
  - Merge 保留真实分支历史，操作安全，团队协作容易理解
  - Rebase 把 feature的提交移动到最新的main之后
    - 会重写Commit历史
  - 常见规则
    - 自己的本地分支 -> 可以 rebase
    - 已经共享出去的公共历史 -> 谨慎 rebase
